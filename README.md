# Психологический курс - Дипломный проект

Интерактивная платформа для прохождения курса по психологии кризиса с системой прогресса и тестированием.

## Стек технологий

- Next.js 16.2.3 (App Router)
- React 19
- TypeScript
- Supabase (Auth + PostgreSQL)
- SCSS Modules
- Server Actions

## Структура проекта

```
/src
  /app
    /page.tsx                    # Главная с Hero Slider
    /sign_in                     # Авторизация
    /sign_up                     # Регистрация
    /dashboard                   # Личный кабинет
    /course                      # Список уроков
    /lesson/[id]                 # Страница урока
    /test                        # Тест на выгорание
    /actions                     # Server Actions
    /certificate                 # PDF-сертификат
    /admin                       # Управление контентом и пользователями
  /data                          # Моковые данные
  /lib/supabase                  # Supabase клиенты
```

## Установка и запуск

1. Установи зависимости:
```bash
npm install
```

2. Настрой Supabase (см. SUPABASE_SETUP.md)

3. Создай `.env.local`:
```env
NEXT_PUBLIC_SUPABASE_URL=твой_url
NEXT_PUBLIC_SUPABASE_ANON_KEY=твой_ключ
```

Для административных операций требуется серверная переменная `SUPABASE_SERVICE_ROLE_KEY`. Роль администратора хранится только в `app_metadata.role` и назначается через Supabase Admin API. `user_metadata` и совпадение email не дают административных прав. Для email-уведомлений используется `RESEND_API_KEY`. Секретные ключи нельзя помещать в переменные `NEXT_PUBLIC_*` или коммитить.

Если администратор был создан старой версией скрипта с ролью в `user_metadata`, назначьте существующему пользователю `app_metadata.role = "admin"` через доверенный Supabase Admin API. Скрипт `scripts/create-admin.mjs` также поддерживает создание и обновление администратора; он обновляет пароль, поэтому запускайте его только намеренно. `ADMIN_EMAIL` служит адресом для этого скрипта, а не проверкой доступа. После изменения роли обновите сессию или войдите заново.

Проверки границы доступа: `npm test` (тесты используют подмену Supabase и не обращаются к рабочей базе).

Если база была настроена по старой инструкции, примените `scripts/restrict-admin-policies.sql` через доверенный Supabase SQL Editor. Он ограничивает старые политики записи контента и чтения заявок ролью `service_role`, сохраняя публичное чтение контента и отправку заявок. Проверьте также другие политики в своей базе: SQL заменяет только перечисленные политики. Изменение файлов репозитория само по себе не изменяет уже развёрнутую базу.

4. Запусти dev сервер:
```bash
npm run dev
```

## Решение проблем

### Email rate limit exceeded
Проверь лимиты отправки писем и настройки SMTP в Supabase Dashboard. Используй отдельный проект для разработки.

### Ошибка supabaseKey is required
Проверь что `.env.local` создан и содержит правильные ключи
